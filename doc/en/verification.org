* Tested environment and scope

Verified on 2026-10-21 (Asia/Shanghai), Linux x86_64, Zig 0.17.0.
CPU: 11th Gen Intel(R) Core(TM) i7-11700 @ 2.50GHz. Host: Linux-6.17.0-40-generic-x86_64-with-glibc2.42.
Evidence covers the uncommitted implementation, not a versioned release.
No full workspace/library delivery build or long soak was run; the example and
benchmark were explicitly compiled as focused artifacts.

* Correctness and engineering

- Debug and ReleaseFast: formatting/compiler checks passed; native shared suite
  completed 18/18 build steps, 14/14 unit tests, eight process scenarios, two
  local consumer checks and one external package consumer check per profile.
- Unit tests cover strict configuration/diagnostics, one-pass path expansion,
  zpp/zust fixture loading, pattern/JSONL formats, invalid UTF-8 escaping,
  calendar/DST/2038+, TZif v1-v4 and every truncated fixture prefix, and
  configuration/timezone/runtime allocation-failure cleanup.
- Scenarios cover sync routing/filtering, four async producers with capacity 2
  and 2,000 unique records, output failure isolation, startup/oversized rotation,
  periodic flush, long payload ownership, 70 distinct short thread numbers with
  caller source metadata, and shutdown during in-flight formatting.
- Debug compiled warn cutoff and ReleaseFast release-only off cutoff passed
  =filter-test=. Disabled info/important format strings were not analyzed.
- The independently built consumer imported both public facades and confirmed
  they share the same singleton. A no-component consumer also compiled/ran.
- Forge: eight new Zig adapter tests and 20 existing build-contract tests passed.
  These include read-only/dry-run, exact version, clean/profile/symlink safety,
  run without build, dev ordering, inherited environment and CLI failure/interrupt
  statuses. Actual destructive profile cleanup and interactive interruption were
  not exercised against the working checkout; contracts use isolated fixtures/mocks.
- Release logging example passed in console-only and supplied-config modes using
  the real local timezone. Its important file contained four valid 14-field JSON
  records at warn/error/critical/info with expected component/action tags.
- =readelf -l= showed no interpreter and =readelf -d= showed no dynamic section
  for the release logging example: no libc dynamic dependency. Source build
  modules explicitly set =link_libc=false=.

The intentional =/dev/full= scenario printed one =NoSpaceLeft= diagnostic and
returned the expected flush/shutdown failure; the healthy output remained intact.
This is test evidence, not an unresolved suite failure.

* Bounded ReleaseFast benchmark

Each mode ran in a separate process, with 1,000 warm-up and 20,000 measured calls.
All accepted records were processed, no output failures occurred, and the logger
allocator returned to zero live bytes after shutdown. Raw host-local results are
in =build/zig/release/benchmark-results.json= (regenerable, not source).

Filtered records were neither formatted nor accepted. Short-message modes made
zero measured logger heap allocations. Long mode uses 4,096-byte payloads and
makes two allocations per measured call (format growth and owned queue copy).
Pressure uses four producers and capacity 2, intentionally measuring blocking.
Other async modes use capacity 64. Peak bytes include logger initialization,
exclude Io/thread internals, and are not process RSS. p50/p99 include clock
measurement overhead. Drained throughput includes final userspace flushing,
without fsync or durable storage guarantees. These are single bounded samples,
not spdlog comparisons or latency SLAs. See [[file:../../BUILD.org][reproduction commands]].

* Atomic prefilter and producer scaling validation (2026-10-21)

This section covers the final implementation; the initial acceptance results and
single-round benchmark above remain historical evidence. The same host, exact
Zig 0.17.0 and ReleaseFast were used. Paired processes inherited affinity 0-7
(eight physical cores), without system-wide changes. The baseline was compiled
from the worktree before runtime changes, including the staged implementation.
Its source snapshot and manifest are under =build/prefilter-comparison/baseline/=
and =baseline-manifest.json=. Both binaries use identical benchmark source;
the initial Git HEAD was not substituted for the current implementation.

** Correctness and implementation checks

- Final Debug/ReleaseFast check/test passed. The routing matrix covers all
  thresholds/output switches and explicit important. Isolated scenarios cover
  concurrent level writers, writers overlapping close, important-only, no
  outputs, and disabled queries before init, after init failure and after close.
- Existing in-flight close, flush barrier, deduplication, output-failure isolation
  and allocation-failure checks still pass. Debug warn and ReleaseFast
  release-only off compile-filter checks passed.
- Each profile passed 16 small benchmark smoke cases (filtered/sync/async/mixed
  with 1/2/4/8 producers). Eight invalid CLI cases were rejected. Each profile
  additionally ran level-race and level-shutdown 20 times each: 80 bounded
  concurrency runs passed in total.
- ReleaseFast ELF inspection confirms one atomic load/bit test and an early
  return before gate access. std.atomic.cache_line is 128 on this target; the
  mask retains 128 bytes and gate begins on the next cache line. A cold-path
  address escape prevents global scalar replacement from removing padding.
  Runtime publication/reclamation retain the existing protocol.

** Paired performance results

Seven independent processes per variant/case, alternating baseline/modified and
reversing pair order each repetition. Every process warms up 1,000 total calls,
then measures two rounds of 200,000 attempted calls each: batch throughput
without per-call clocks, then per-call latency. Producers and samples are
created before warm-up. Timing includes round wake-up/completion notification,
not thread creation, warm-up or joins. Mixed accepts one info per ten attempts,
filters nine debug calls, and uses synchronous file output.

Throughput is millions of attempted calls/s; p99 is ns. Cells show the median
[Q1, Q3] across seven runs, using inclusive interpolated quartiles. Ratio is the
ratio of throughput medians, not the median of individual paired ratios.

Filtered throughput quartiles are clearly separated at 4/8 producers, with gains
also present in mixed workloads. Enabled sync/async batch throughput changes
range from -8.1% to +2.3%; the largest p99 increase is 3.2%. No final enabled case
crosses the 10% review threshold. The single-producer async loss of 8.1% remains
reported: this is not an across-the-board speedup. Pressure/long throughput
ratios are 0.986/0.946 respectively.

All per-round count, formatting, output-failure, short-message allocation and
shutdown-reclamation assertions passed in all 252 final processes. Filtered
rounds accept/format/allocate zero records. Mixed accepts 40,100 total records;
other enabled modes accept 401,000. Long makes 400,000 logger heap allocations
per measured round; all other modes make zero measured logger allocations.

An initial pass exposed removed padding and a sync/2 p99 increase of 10.9%.
After preserving storage, the complete matrix was rerun; final sync/2 p99 ratio
is 0.881. Initial data is retained separately as
=build/prefilter-comparison/initial-scalarized-results.json= and is excluded from
final aggregates. The two passes alone cannot attribute all latency variation
to cache layout.

Raw final samples, binary/source hashes, affinity and all distribution summaries
are in =build/prefilter-comparison/results.json=. The local driver is
=run_comparison.py= in that directory, alongside =baseline-benchmark= and
=optimized-benchmark=. These are regenerable verification artifacts, not staged
source. See [[file:../../BUILD.org][the benchmark guide]] for measurement semantics.

Results compare this z.log before/after only. Fixed %v, short payloads, page-cache
file writes, the shared formatter atomic counter and barrier overhead affect the
numbers. Filtered calls/s are not persisted-record throughput; p99 includes
sampling clocks. No equivalent spdlog comparison, fsync benchmark, full delivery
build, other-platform run, sanitizer or prolonged stress/soak was performed.
No version change, commit or push; the original index is preserved.

* Overflow policy verification — 2026-10-21

Earlier sections retain pre-change evidence; this entry supersedes their
blocking/no-loss assumptions. Zig 0.17.0, Linux x86_64.

- Debug and ReleaseFast: native =zig build test --summary all= passed 22/22
  steps and 17/17 unit tests, including all twelve process scenarios and the
  independent consumer. Forge =check= also passed both profiles.
- A gated worker with capacity one proves four producers finish with 80 dropped
  records across levels/important routing and 4 KiB payloads, preserves the
  queued record, reliably processes a flush barrier, and reclaims allocator
  ownership. Controlled clocks verify report throttling and forced final deltas.
- Async public scenarios verify accepted + dropped = attempted, processed =
  accepted after flush, and readable final statistics after concurrent shutdown.
  Metadata checks avoid overload; actual /dev/full failure remains an error.
- The benchmark executable was built as a focused ReleaseFast artifact. Bounded
  pressure/long/sync smokes used 2,000 calls per measured round, plus warm-up;
  conservation and allocator cleanup passed. Sync dropped zero; pressure short
  messages had zero hot allocations. These are correctness smokes, not a
  before/after performance comparison or sustained-load acceptance.
- No full library delivery build, application/live trading run, sanitizer,
  long soak, dependency upgrade, commit or deployment was performed.
