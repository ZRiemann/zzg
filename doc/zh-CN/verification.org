* 正确性与工程验证

- Debug 和 ReleaseFast 的格式/编译检查通过；每个 profile 原生共享套件
  18/18 构建步骤通过，包括 14/14 单元测试、8 个独立进程场景、2 个本地消费端
  检查及 1 个独立包消费端检查。
- 单元测试覆盖严格配置/诊断、单次路径展开、zpp/zust 配置夹具加载、pattern/
  JSONL、非法 UTF-8 转义、日历/夏令时/2038 年之后、TZif v1-v4 及夹具每个
  截断前缀、配置/时区/运行时分配失败回收。
- 场景覆盖同步路由/过滤、4 个异步生产者和容量 2 队列的 2,000 条唯一记录、
  输出失败隔离、启动/超长消息轮转、周期刷新、长消息所有权、70 个不同短
  线程号与调用点源码，以及在途格式化期间关闭。
- Debug 编译阈值 warn 和 ReleaseFast 仅 release 阈值 off 的 =filter-test=
  通过；被裁掉的 info/important 无需分析其中无效的格式字符串。
- 独立构建的消费端同时导入两种公共入口，确认共享单例；未启用组件的消费端
  也通过编译和运行。
- Forge 新增 8 项 Zig 适配器测试及原有 20 项构建契约测试全部通过，覆盖
  只读/dry-run、精确版本、profile/链接清理边界、run 不构建、dev 顺序、
  环境继承及失败/中断退出码。未对当前工作区执行破坏性 profile 清理或交互式
  中断；相关契约通过隔离文件系统和模拟进程验证。
- Release 日志示例通过纯控制台及所附配置运行，使用实际本地时区。important
  文件包含 4 条有效 JSON，均为 14 字段，级别依次 warn/error/critical/info，
  component/action 符合预期。
- Release 示例经 =readelf -l= 检查无 interpreter，=-d= 检查无动态段，
  没有 libc 动态依赖；源码模块显式设置 =link_libc=false=。

=/dev/full= 故障场景有意输出一次 =NoSpaceLeft=，flush/shutdown 返回预期
错误，正常输出文件仍完整。这是故障验收证据，不是未解决的套件失败。

* 有界 ReleaseFast 基准

各模式独立进程运行，预热 1,000 次，测量 20,000 次。所有已接受记录均已处理，
无输出失败，关闭后日志 allocator 存活字节归零。原始本机结果保存在可再生的
=build/zig/release/benchmark-results.json=，不作为源码提交。

filtered 不格式化、不接受记录。短消息模式测量区间内无日志堆分配。long 为
4,096 字节消息，每次有两次分配：格式缓冲增长和队列自有副本。pressure 使用
4 生产者、容量 2，有意测量阻塞；其他异步模式容量 64。峰值包含初始化，不含
Io/线程内部资源，不等同进程 RSS。p50/p99 包含计时开销；含排空吞吐包括最终
用户缓冲刷新，不含 fsync，也不代表持久存储吞吐。数据为单次有界采样，不是
spdlog 对比或延迟 SLA。复现方式见[[file:../../BUILD.org][构建指南]]。

** 正确性与实现核对

- 最终源码的 Debug/ReleaseFast =check=、=test= 均通过；新增路由矩阵覆盖
  全部阈值、输出开关及显式 important，独立进程覆盖级别并发更新、更新期间
  关闭、important-only、无输出配置，以及初始化前、失败后、关闭后的禁用状态。
- 原在途格式化关闭、flush 屏障、去重、输出故障隔离和分配失败测试保留并通过。
  Debug warn 与 ReleaseFast release-only off 两组编译过滤检查通过。
- Debug/ReleaseFast 基准各通过 16 组小规模冒烟（filtered/sync/async/mixed ×
  1/2/4/8 生产者）；8 组非法 CLI 参数被拒绝。两种 profile 各额外运行
  level-race、level-shutdown 各 20 次，共 80 次有界并发场景，均通过。
- 核对 ReleaseFast ELF：过滤入口为一次原子 load、位测试及返回分支，禁用时
  不触碰 gate。std.atomic.cache_line 在本目标为 128；位图符号保留完整
  128 字节，gate 位于下一缓存行。初始化处使用冷路径地址逃逸，防止编译器
  对全局变量的标量替换删除填充。Runtime 发布/回收协议保持不变。

次，然后执行两轮各 200,000 次调用：无逐调用时钟的批量吞吐轮、逐调用延迟轮。
线程在预热前创建，样本提前分配；计时包含轮次唤醒和完成通知，不包含创建、
预热和 join。mixed 每十次接受一次 info，其余 debug 被过滤；同步文件输出。

4/8 生产者过滤吞吐的四分位范围与基线清晰分离，混合负载亦有收益。
已启用 sync/async 的批量吞吐变化范围为 -8.1% 至 +2.3%，p99 最大增幅
为 3.2%，均未触发本次 10% 复核门槛。单生产者 async 的 -8.1% 如实保留，
不将结果概括为所有负载都加速。pressure/long 吞吐倍率分别为 0.986/0.946。

所有最终 252 次进程运行的每轮格式化次数、accepted/processed、输出错误、
短消息分配及关闭回收断言均通过。filtered 每轮接受/格式化/分配均为零；
mixed 最终接受 40,100 条，其他有效模式接受 401,000 条。长消息每个测量轮
有 400,000 次日志堆分配，其余模式测量轮均为零。

初轮发现编译器消除填充，并出现 sync/2 的 p99 +10.9% 门槛告警；修正存储后
完整重测，最终 sync/2 p99 比率为 0.881。初轮数据保留为
=build/prefilter-comparison/initial-scalarized-results.json=，不混入最终汇总；
不能仅凭两轮结果将全部延迟波动归因于缓存布局。

最终原始数据、二进制/源码哈希、CPU 绑定、全部中位数及四分位保存在
=build/prefilter-comparison/results.json=；本地复现驱动为同目录
=run_comparison.py=，基线/优化二进制为 =baseline-benchmark= 和
=optimized-benchmark=。这些均为可再生验证产物，不作为源码暂存。
计时口径见 [[file:../../BUILD.org][构建与基准指南]]。

本数据仅比较当前 z.log 改造前后。固定 %v、小消息、页缓存文件写入、共享
formatter 原子计数及屏障开销均影响结果；过滤吞吐不是实际落盘吞吐，p99 包含

- Debug、ReleaseFast 的原生 =zig build test --summary all= 均通过 22/22 步骤、
  17/17 单元测试，含十二个进程场景及独立消费者；两种配置的 Forge =check= 均通过。
- 容量一的受控 worker 验证四个生产者满时返回、跨级别/important 路由及 4 KiB
  消息累计丢弃 80 条、保留原记录、可靠 flush 屏障及分配所有权回收。
  可控时钟覆盖告警限频及关闭补报。
- 公共异步场景校验接收 + 丢弃 = 尝试，flush 后处理 = 接收，并发关闭后统计
  仍可读取。元数据场景避免过载，真实 /dev/full 故障继续报告错误。
