* 目标与范围

交付 ZetaX 顶层 =z= 命名空间、原生 Zig/Forge 工程边界和纯 Zig 日志组件，
兼容当前 zpp 配置及 zust pattern 子集。基线为精确 Zig 0.17.0、Linux x86_64，
不链接 libc、不引入第三方日志后端。整体状态：已验收、待版本化交付。
实际版本化交付在获授权的版本提交前保持未设置。

不包含其他基础组件、完整 spdlog pattern、动态后端插件、多进程共享日志文件、
配置/时区热更新、闰秒、其他平台运行验收，也不宣称已具备行业生产成熟度。

* 架构与所有权

依赖方向为 =z facade -> log runtime -> config/time/format/output=。
共享类型承载值契约，基础模块不依赖 facade 或应用业务策略。通用与独立入口
复用同一个模块对象；编译期级别和类型驱动的 JSON 字段加载直接采用 Zig
特性，不建立额外转发层或动态输出注册表。

应用拥有 allocator、Io、环境及生产者停止顺序；运行时拥有不可变配置和时区
快照、已编译 pattern、文件缓冲、队列及 worker/flusher。每进程仅一次成功
初始化，失败不发布运行时。关闭先停止接收，等待引用、排空并 join，之后释放
内存。静态短临界区和静态 futex 引用计数使生命周期协调不依赖可释放对象。
过滤快照由同一路由函数派生，存放于独立缓存行的静态原子位图；控制路径在
生命周期 gate 内更新。位图只负责提前排除调用，不发布 Runtime，不替代引用
保护；已通过预过滤的调用仍复查路由。setLevel 与关闭串行，不能在关闭后
重新发布启用位图。状态为 fresh -> initializing -> ready -> closing -> closed，初始化失败回到
fresh。不支持格式化函数重入 shutdown/flush。

热路径约束：被过滤调用不格式化、不分配；短消息采用栈存储和内联队列槽，
渲染及文件缓冲复用。异步队列满时丢新并独立统计，flush 屏障保持可靠；长消息显式分配。单 worker
确定接受顺序，单个输出失败可观察且不阻断其他输出。

Forge 拥有共享 Zig 适配器、工具链检查和安全的 profile 清理；zzg 拥有原生
构建 step、模块、测试、样例及公共配置。zpp/zust 为只读兼容参照。通过原生
测试、固定记录/时间、确定性时区夹具和隔离进程场景验证，无需公共插件系统。

* Stage 1.1 — 工程与命名空间

- 归属：zzg；跨仓前置为 zeta_forge 的 Zig 支持。
- 交付：可选通用 =z= 入口、独立 =z.log= 入口、包元数据、原生检查/消费端、
  薄启动器与 Forge 适配器。
- 验收：精确版本、只读命令/dry-run、profile 隔离、run 不隐式构建、独立
  消费工程及共享唯一运行时。
- 证据：[[file:verification.org][验证记录]]。状态：已验收、待版本化交付；实际交付版本未设置，
  zzg 初始计划版本为 0.1.0。

* Stage 1.2 — 配置、时间与格式

- 归属：zzg；前置 Stage 1.1。
- 交付：严格 zpp JSON 映射、自有配置内存、路径展开、zust pattern 子集、
  JSONL 标签/转义、TZif 及 POSIX 夏令时规则。
- 验收：zpp/zust 夹具、非法字段/溢出、全部支持标记、固定元数据、日历/
  夏令时/2038 年之后、损坏/截断时区夹具及分配失败回收。
- 证据：[[file:verification.org][验证记录]]。状态：已验收、待版本化交付；实际交付版本未设置。

* Stage 1.3 — 同步输出与路由

- 归属：zzg；前置 Stage 1.2。
- 交付：控制台、缓冲轮转文件、important 通道、普通过滤、显式刷新和错误。
- 验收：目的地计数、important 去重、阈值、完整超长记录、启动/容量轮转、
  单输出失败不影响其他输出、被过滤记录不调用格式化。
- 证据：[[file:verification.org][验证记录]]。状态：已验收、待版本化交付；实际交付版本未设置。

* Stage 1.4 — 异步生命周期与集成

- 归属：zzg；前置 Stage 1.3。
- 交付：有界队列、单 worker、周期刷新、完成屏障、幂等并发关闭、生产者
  元数据与自有数据交接、独立性能基准。
- 验收：多生产者容量 2 队列、记录唯一/完整、长消息所有权、超过 64 的短
  线程号、调用点源码、关闭时在途格式化、Debug/ReleaseFast 及编译过滤、
  ELF 无 libc 依赖、可复现的分配/延迟/吞吐报告。
- 证据：[[file:verification.org][验证记录]]。状态：已验收、待版本化交付；实际交付版本未设置。

* 整体验收及边界

整体须通过集成共享套件和示例，不能只以 Stage 勾选作为完成依据。0.1.0
版本元数据已准备，不代表已提交发布；Forge 适配器通过验收也不意味着 Forge
已升级或发布。不包含提交/推送、完整工作区构建、长期压力、sanitizer 和其他
平台验收。后续优化须保留上述契约，并以可重复基准支持复杂度增加。
